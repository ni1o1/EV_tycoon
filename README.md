# EV 大亨 · 一度电，一座城

[在线游玩](https://ni1o1.github.io/EV_tycoon/) · 原生 JavaScript / Canvas 充电站经营模拟游戏。

## v3.0 · 从单桩教学到长线成长战役

- 主屏明确显示当前电网单价（$/kWh）、最近十分钟售电收入（+$）与实际购电费（−$）；储能从电网充电也会计入电费，光伏供电与离网时不产生购电费。
- 手机主屏固定为一个视口，保留原版的资金与实时增减、昨日净收支、天气效率与预报、客流、日维护、每日还款、租金倒计时、事件状态、实时功率、储能状态、电价与设备操作。
- 24 小时能源曲线始终显示在主屏：昨日电网、光伏供车、储能供车、电网进口及新增充电负荷；点按可查看时刻功率（kW）。曲线来自实际十分钟调度，不用平滑曲线改变峰值。
- 站点采用手绘矢量场景，车辆有车窗、车轮、车灯和车身立体面，充电桩有屏幕、枪与线缆；光伏屋顶、储能柜和车辆充电进度对应实际设备状态。实际客户从道路驶入，充满或超时后驶出；动画随暂停冻结、支持减少动态效果，渲染与收费相互独立。
- 8 类模拟车辆有不同容量与交流/直流充电上限；到站 SOC 使用截断正态分布 N(20%, 7%²)，限制 5%～50%。车旁显示容量、SOC、实际功率/车辆上限；计费只包含到站后新增的电量。
- 十个模式预设在一屏选关页直接展示，包含各关模式与经营时长；目标说明、准备金和历史账本按需点开，玩法指南分三页，减少常驻信息。
- 第一关从 1 台慢充桩开始，仅开放慢充和配电。按真实营业成就解锁推广、快充、光伏、储能及银行；解锁跨关保留，教学关重玩仍按课程逐步开放。
- 十个递进关卡，经营时长从 28 天延长至 120 天，覆盖原有九种模式。通关后可继续经营当前站，或以新预设进入下一关；技术解锁保留。
- 自动保存当前经营局，刷新后可恢复；保留已解锁关卡。存档仅保存在当前浏览器，开始新局替换当前存档。
- 默认暂停，手动开始；支持 1× / 4× / 8×，空格暂停，切到后台自动暂停。贷款、账单、事件窗口打开时暂停。
- 按实际交付电量收费，最后一次充电不会少收或重复计费。离网模式禁止购电、缺电限速，储能遵守容量与充放电功率限制。
- 贷款采用模拟日利率 2%，预览与实际还款使用同一算法。每日收支包含维护、贷款还款及当日支付的租金，不包含设备投资、贷款入账和随机事件。
- 运行时依赖本地提供，不需要 Tailwind CDN 或 ECharts CDN。手机布局始终显示定价、设备购买与速度控制；支持键盘与减少动态效果偏好。

## 成长与解锁

开局一台慢充桩、20 kW 基础配电，可购买慢充与配电。已解锁技术保存在当前浏览器中，进入后续关卡和重开游戏都会保留；教学关从基础操作重新按课程开放，其他关卡使用账号已解锁的技术。已有设备即使其采购尚未开放，也能正常工作。模式限制优先：超充不能买慢充，离网不能买配电。

| 开放项目 | 同时需要达成的条件 | 每局一次的成就补贴 |
| --- | --- | ---: |
| 推广 | 营业满 7 天，充满 8 辆车 | $300 |
| 快充 | 营业满 14 天，交付 800 kWh | $800 |
| 光伏 | 营业满 21 天，交付 1,800 kWh | $600 |
| 储能 | 营业满 28 天，拥有 2 组光伏 | $500 |
| 银行 | 营业满 35 天，充满 80 辆车 | $1,000 |

营业天数按已完成的游戏日计算，必须先支付到期租金、保持资金非负，才确认成就。解锁和补贴都由真实经营状态触发，存档恢复不会重复发放同一局已领补贴。补贴即使技术以前已解锁，也可在新局完成条件后领一次；不同局资金彼此独立，不能积累重复入账。补贴与设备投资、贷款到账及随机事件一样，不属于日常售电毛利和日净收支。

主屏站点上方显示下一项解锁的天数、车辆或电量进度；点击可查看完整条件及补贴领取状态。尚未开放的设备和银行保持可见。能源曲线、购电单价、电费、售电收入与全部操作继续留在单屏。

## 模式战役

| 关卡 | 原模式 | 期限 | 初始资金 | 通关目标 |
| --- | --- | ---: | ---: | --- |
| 街角开业 | 标准 · 单桩教学 | 28 天 | $1,800 | 至少 2 台桩，交付 1,800 kWh |
| 阳光合伙 | 标准 · 光储成长 | 45 天 | $2,600 | 2 组光伏、1 组储能，充满 100 辆，净资金 $2,000 |
| 超充时代 | 超充狂热 | 60 天 | $4,200 | 4 台快充，交付 30,000 kWh，净资金 $5,000 |
| 冷清街区 | 鬼城危机 | 65 天 | $4,000 | 充满 180 辆，交付 15,000 kWh，净资金 $3,000 |

| 离网绿洲 | 离网挑战 | 75 天 | $5,500 | 6 组光伏、4 组储能，交付 18,000 kWh，净资金 $3,000 |
| 漫长雨季 | 永恒雨季 | 80 天 | $7,000 | 8 台桩，交付 45,000 kWh，净资金 $10,000 |
| 繁华商圈 | 豪华地段 | 90 天 | $7,500 | 14 台桩、其中 6 台快充，净资金 $45,000 |
| 成本风暴 | 恶性通胀 | 100 天 | $9,000 | 10 台桩、5 台快充、4 组光伏、4 组储能，净资金 $25,000 |
| 资金长跑 | 高频租金 | 120 天 | $11,000 | 12 台桩、6 台快充，交付 150,000 kWh，净资金 $60,000 |

每关期限与全部目标都要完成，资金不能破产，到期租金必须先支付。净资金为账户余额减未还贷款本金，不能靠临近结束借款凑目标。通关一星，两星和三星的净资金门槛随关卡增长，具体数值显示在关卡目标中。每关有明确初始设备、客流、城市、电价和租金预设；教学关免随机事件，后续保留天气及事件的不确定性。

按 144 个十分钟回合/游戏日估计，28 天在 1× 下约 33 分钟、8× 下约 4 分钟；120 天在 1× 下约 144 分钟、8× 下约 18 分钟。实际时长会受到开始时间、暂停和账单/事件操作影响。通关后「继续经营这座站」保留现金、设备和顾客，仍可继续解锁；「下一关」使用独立预设并保留技术成果。

各模式独立机制保留：鬼城客流减半；限电配电每次仅 +10 kW；离网禁止购电、采购优惠 25%，初始存电 150 kWh；雨季持续降雨；豪华客流翻倍且售价接受度更高；通胀同类设备每次涨价 50%；高频租金每 3 天结算。战役使用各关预设租金，通胀关为每周线性递增 $160；自由经营的通胀租金仍保留原指数增长。

设备基础采购价/日维护：慢充 $800/$12，快充 $2,400/$35，光伏 $1,200/$8，储能 $1,800/$18，配电 $1,000/$15；普通模式同类连续采购递增 10%，事件折扣仍生效。

`npm run balance -- 12` 用真实客流、车型、天气、事件、调度、成就和结算规则进行回放，比较挂机与规划投资。后续关卡按真实前置通关可获得的技术来初始化账号，首关和第二关仍在局内达成开放条件。12 个固定种子（171 的整数倍）中，挂机在十关均未完成全部目标；参考扩建策略在第三关为 10/12，其余为 12/12。参考策略不是最优解，结果仅代表这些场景，不代表玩家总体通关率；配电、桩与光储的逐步采购计划见 `scripts/balance.cjs`。

旧版星级记录以「旧★」展示，新战役单独评星；旧关卡解锁映射到相应模式和后续关卡，旧记录不删除。正在经营的 v2 存档恢复为经典关卡，保留原期限、租金和目标；继续营业保持当前站点，重试或进入下一关使用对应的新预设。自由经营仍可恢复旧局。

自由经营保留标准、超充、离网、鬼城、豪华、限电、通胀、雨季、高频租金九种模式，目标生存 100 天。城市分时电价为游戏参数，并非实时商业电价。

## 车辆模型

以下是用于探索调度逻辑的虚构车型参数，不对应某个品牌或具体型号。充电至 100%；当前模型使用恒定的接受功率上限，尚未模拟接近满电时的充电降功率。实际功率受车辆交流/直流上限、桩功率、站点配电及可用能源共同约束。标准快充桩额定 30 kW，因此即使车辆支持 150 kW，也只会接受不超过桩与站点允许的功率。

| 车型 | 容量 kWh | AC 上限 kW | DC 上限 kW |
| --- | ---: | ---: | ---: |
| 紧凑车 | 42 | 3.6 | 25 |
| 出租车 | 58 | 7 | 60 |
| SUV | 82 | 11 | 120 |
| 跑车 | 70 | 11 | 150 |
| 巡逻车 | 62 | 11 | 90 |
| 救护车 | 86 | 22 | 100 |
| 厢式车 | 76 | 7 | 50 |
| 皮卡 | 110 | 11 | 180 |

原有存档中已到站、尚无车型参数的车辆保留原来的待充电量和功率规则，驶离后新客户使用新的车型模型。曲线与存档继续兼容 v2。

## 本地运行

```bash
python3 -m http.server 4175 --directory docs
```

打开 `http://localhost:4175/`。运行游戏不需要安装 Node 依赖。

修改样式或运行检查：

```bash
npm ci
npm run build
npm test
npx playwright install chromium
npm run test:layout
npm run balance
```

`npm run build` 将 Tailwind 工具类编译到 `docs/utilities.css`，产物需一并提交。主要自定义样式在 `docs/style.css`。

## 文件结构

- `docs/index.html`：正式入口与语义化界面。
- `docs/campaign.js`：关卡、经营提示、自动存档和增强交互。
- `docs/game.js`：时间循环、设备、客流、事件、结算、站点绘制。
- `docs/vehicles.js`：车型容量、接受功率、初始电量分布与 SOC。
- `docs/station-art.js`：车辆、充电桩与站点矢量美术，独立于调度逻辑。
- `docs/energy.js`：供电调度与实际电量计费。
- `docs/finance.js`：贷款预览、还款和最终本金结清。
- `docs/vendor/`：本地 ECharts 及其许可证。
- `scripts/balance.cjs`：用真实游戏规则进行可复现的数值回放。
- `tests/`：能源守恒、离网、贷款、暂停、存档、目标和完整通关回归测试。
- `docs/index_test.html`：旧测试地址，自动跳转正式版。

## 部署

GitHub Pages 使用 `main` 分支的 `/docs` 目录，推送后由 GitHub 自动发布。
`Game checks` 工作流运行回归测试、真实浏览器单屏与弹窗检查，并核验工具类 CSS 产物。部署后检查 Pages 构建状态及线上脚本文件是否对应提交。

游戏代码沿用项目标注的 MIT 许可证；ECharts 为 Apache-2.0，许可证与 NOTICE 位于 `docs/vendor/`。
